# Kagiroi Kotlin SQL cheat sheet

Kotlin syntax reference for Kagiroi.
`// SQL:` comments show the equivalent SQL; `?` is a bound Kotlin value.
The selected dialect decides quoting, placeholders, and dialect-specific syntax.

- `Table` defines a table. The database does not change until `createTable` runs.
- The `T` in `Column<T>` and `SqlExpression<T>` is the Kotlin read/write type.
  `nullable()`, an outer join's `.optional`, and aggregate results produce `T?`.
- `select`, `insertInto`, `update`, and `deleteFrom` build statements.
  `all()`, `one()`, and `execute()` run them.

The snippets omit imports and unrelated model declarations.
Import table definitions from `dev.quwac.kagiroi.schema` and queries and DDL from
`dev.quwac.kagiroi.sql`.
Import dialect-specific APIs from that dialect's module.

## Tables and columns

Define a table with `object : Table`.
Columns are `NOT NULL` by default.
Use `nullable()` only when both Kotlin and the database may hold NULL.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE app.users (
//   id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
//   email VARCHAR NOT NULL UNIQUE,
//   display_name VARCHAR NULL
// )
object Users : Table(
    tableName = "users",
    schemaName = "app",
    comment = "Application users",
) {
    val id = long("id").identity().primaryKey()
    val email = string("email").unique().comment("Login address")
    val displayName = string("display_name").nullable()
}
```

| Declaration | Kotlin type |
| --- | --- |
| `string(name)` | `String` |
| `byte`, `short`, `int`, `long` | `Byte`, `Short`, `Int`, `Long` |
| `ubyte`, `ushort`, `uint`, `ulong` | Corresponding unsigned type |
| `float`, `double` | `Float`, `Double` |
| `boolean`, `bytes` | `Boolean`, `ByteArray` |
| `uuid`, `instant`, `duration` | `Uuid`, `Instant`, `Duration` |
| `column(name, type)` | A `ColumnType<T>` supplied by an extension module |

| Modifier | Meaning |
| --- | --- |
| `.nullable()` | Changes `Column<T>` to `Column<T?>` |
| `.primaryKey()` / `.unique()` | Primary key / unique constraint |
| `.index(name, unique = false, comment = null)` | One-column migration-managed index |
| `.default(value)` | Value when INSERT omits the column |
| `.identity()` / `.identity(startWith = ..., incrementBy = ...)` | Database-generated `Long` value |
| `.generated(expr, storage)` | Read-only generated column |
| `.computed()` | Read-only column omitted from DDL |
| `.comment(text)` | Table-definition description |
| `.renamedFrom(previous, ...)` | Ordered migration-only physical name lineage |
| `.transform(...)` / `.asEnum(...)` | Kotlin value-to-storage mapping |

Each modifier returns the updated column.
Keep that result in a `val` when later declarations need it.
Call `default(...)` after `transform(...)`.

### Index declarations

An index belongs to its `Table` definition.
Use the column modifier for one key, and an `init` block for composite or advanced indexes.

```kotlin
object Users : Table("users") {
    val id = long("id").identity().primaryKey()
    val displayName = string("display_name").index("users_display_name_idx") {
        renamedFrom("users_name_idx")
    }
    val email = string("email")
    val active = boolean("active")

    init {
        index("users_display_name_email_idx", unique = true) {
            renamedFrom("users_name_email_idx")
            on(displayName, email)
        }

        index("users_active_email_idx") {
            on(lower(email).asc())
            include(id)
            where(active eq true)
        }
    }
}
```

`on(...)` preserves key order and accepts columns, typed expressions, and `.asc()` / `.desc()`.
`where(...)` declares a partial or filtered index.
`include(...)` declares covering columns.
`renamedFrom(...)` records ordered Index name lineage for migration planning only.
Dialect support for expression keys, predicates, directions, and INCLUDE columns varies.

`createTable(Users)` creates only the table.
Run the table-declared indexes with `createIndexes(Users)` so no index is declared twice.
`createIndex(...)` remains for an explicit one-off DDL operation and does not add migration metadata.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE order_lines (
//   price INTEGER NOT NULL,
//   quantity INTEGER NOT NULL,
//   total INTEGER GENERATED ALWAYS AS (price * quantity) STORED,
//   normalized_email VARCHAR GENERATED ALWAYS AS (LOWER(email)) STORED
// )
object OrderLines : Table("order_lines") {
    val price = int("price")
    val quantity = int("quantity")
    val email = string("email")
    val total = int("total").generated(price * quantity, GeneratedColumnStorage.Stored)
    val normalizedEmail = string("normalized_email")
        .generated(lower(email), GeneratedColumnStorage.Stored)
}
```

Generated columns can use columns from the same table, supported functions, arithmetic, and
`case`.
They cannot use subqueries, aggregates, or window functions.
Choose `Virtual` or `Stored` explicitly.

### Custom types and enums

Use a value object even when its storage representation is `String`.
Declare every stored enum value; never depend on enum ordinals.

```kotlin
data class AccountId(val value: String)

val accountIdMapping = columnMapping(::AccountId, AccountId::value)

// SQL (when createTable runs): CREATE TABLE accounts (id VARCHAR NOT NULL, owner_id VARCHAR NOT NULL)
object Accounts : Table("accounts") {
    val id = string("id").transform(accountIdMapping)
    val ownerId = string("owner_id").transform(::AccountId, AccountId::value)
}

enum class Status { Draft, Published }

// SQL (when createTable runs): CREATE TABLE posts (status VARCHAR NOT NULL)
object Posts : Table("posts") {
    val status = string("status").asEnum(Status.entries) {
        Status.Draft mapsTo "draft"
        Status.Published mapsTo "published"
    }
}
```

### Primary keys, UNIQUE, foreign keys, and CHECK

Put a single-column constraint on its column.
Use `init` for multi-column or named constraints.
Choose either a column-level or table-level primary key for a table.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE organization_users (
//   organization_id UUID NOT NULL,
//   user_id UUID NOT NULL,
//   email VARCHAR NOT NULL,
//   CONSTRAINT pk_organization_users PRIMARY KEY (organization_id, user_id),
//   CONSTRAINT uq_organization_users_email UNIQUE (organization_id, email)
// )
object OrganizationUsers : Table("organization_users") {
    val organizationId = uuid("organization_id")
    val userId = uuid("user_id")
    val email = string("email")

    init {
        primaryKey(organizationId, userId, name = "pk_organization_users")
        unique(organizationId, email, name = "uq_organization_users_email")
    }
}
```

A foreign-key column has the target's Kotlin type and storage mapping.
Call `nullable()` before `SET NULL`, and `default(...)` before `SET DEFAULT`.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE orders (
//   id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
//   owner_id BIGINT NOT NULL,
//   CONSTRAINT fk_orders_owner FOREIGN KEY (owner_id) REFERENCES users(id) ON DELETE CASCADE
// )
object Orders : Table("orders") {
    val id = long("id").identity().primaryKey()
    val ownerId = foreignKey("owner_id", Users.id, constraintName = "fk_orders_owner")
        .onDelete(ForeignKeyAction.Cascade)
}

// SQL (when createTable runs):
// CREATE TABLE optional_orders (
//   optional_owner_id BIGINT NULL REFERENCES users(id) ON DELETE SET NULL
// )
object OptionalOrders : Table("optional_orders") {
    val optionalOwnerId = foreignKey("optional_owner_id", Users.id)
        .nullable()
        .onDelete(ForeignKeyAction.SetNull)
}
```

For a composite foreign key, use
`foreignKey(local1, local2).references(remote1, remote2)`.
Kagiroi does not create an index or a Kotlin relation object from a foreign key.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE checked_orders (
//   quantity INTEGER NOT NULL,
//   note VARCHAR NULL,
//   CONSTRAINT quantity_positive CHECK (quantity > 0),
//   CHECK (quantity > 0 AND quantity <= 100),
//   CONSTRAINT note_not_empty CHECK (LENGTH(note) > 0)
// )
object CheckedOrders : Table("checked_orders") {
    val quantity = int("quantity")
    val note = string("note").nullable()

    init {
        checkConstraint("quantity_positive") { quantity gt 0 }
        checkConstraint { (quantity gt 0) and (quantity lte 100) }
        checkConstraint("note_not_empty") { length(note) gt 0 }
    }
}
```

Use `gt`, `gte`, `lt`, `lte`, `eq`, and `neq`, not Kotlin's `>`.
A CHECK is a Boolean expression that references at least one column of the same table.
It cannot use aggregates, window functions, or a column from another table.

## DEFAULT, identity, and sequences

Defaults fill omitted INSERT columns, identities allocate a column value, and sequences are
independent number sources.

```kotlin
// SQL (when createTable runs):
// CREATE TABLE numbered_orders (
//   id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
//   attempts INTEGER NOT NULL DEFAULT 0,
//   created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
//   display_number BIGINT NOT NULL DEFAULT (nextval('app.order_numbers') + 10)
// )
object NumberedOrders : Table("numbered_orders", schemaName = "app") {
    val orderNumbers = sequence("order_numbers")
    val id = long("id").identity().primaryKey()
    val attempts = int("attempts").default(0)
    val retryLimit = int("retry_limit").default(defaultExpression(1) + 2)
    val createdAt = instant("created_at").default(currentInstant())
    val displayNumber = long("display_number").default(orderNumbers.nextValue() + 10L)
}

// SQL: CREATE SEQUENCE app.order_numbers;
//      CREATE TABLE numbered_orders (...);
//      SELECT NEXT VALUE FOR app.order_numbers;
//      DROP TABLE numbered_orders; DROP SEQUENCE app.order_numbers;
val reservedNumber: Long = database.execute {
    createSequence(NumberedOrders.orderNumbers)
    createTable(NumberedOrders)
    val number = nextSequenceValue(NumberedOrders.orderNumbers)
    dropTable(NumberedOrders, ifExists = true)
    dropSequence(NumberedOrders.orderNumbers, ifExists = true)
    number
}
```

`default(value)` uses the column's conversion rules.
An expression default has the column's type and cannot reference columns, subqueries, aggregates,
or window functions.
`default(null)` means `DEFAULT NULL` for a nullable column; it differs from no default.

Sequences work with PostgreSQL/PGlite, MariaDB, SQL Server, and Oracle.
SQLite/D1 and MySQL reject sequence operations.

`identity()` is separate from `sequence` and is available only on `Long` columns.
Use `startWith` for the first database-generated value and `incrementBy` for the
difference between values:

```kotlin
// SQL (PostgreSQL/PGlite):
// CREATE TABLE event_log (
//   id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000 INCREMENT BY 10) PRIMARY KEY
// )
object EventLog : Table("event_log") {
    val id = long("id")
        .identity(startWith = 1000L, incrementBy = 10L)
        .primaryKey()
}
```

Leaving both options out uses the database defaults. `incrementBy = 0L` is rejected.
PostgreSQL/PGlite and Oracle render native options; SQL Server renders its required
seed/increment pair. MySQL/MariaDB render `startWith` as a table-level `AUTO_INCREMENT`
option and reject `incrementBy`; SQLite/D1 reject both options.

| Dialect | Identity | Generated columns | Independent sequence |
| --- | --- | --- | --- |
| SQLite / D1 | `INTEGER PRIMARY KEY`; no identity options | `VIRTUAL` and `STORED`; only virtual can be added | Unsupported |
| PostgreSQL / PGlite | `GENERATED BY DEFAULT AS IDENTITY`; start/increment supported | `STORED` | Supported |
| MySQL | `AUTO_INCREMENT`; `startWith` is table-level | `VIRTUAL`, `STORED` | Unsupported |
| MariaDB | `AUTO_INCREMENT`; `startWith` is table-level | `VIRTUAL`, `PERSISTENT` | Supported |
| SQL Server | `IDENTITY(seed, increment)` | `AS (...)`, optionally `PERSISTED` | Supported |
| Oracle 23ai+ | `GENERATED BY DEFAULT AS IDENTITY`; start/increment supported | `VIRTUAL`, `MATERIALIZED` | Supported |

`computed()` is a logical read-only column and has no physical generated-column DDL.
Generated columns are read-only; `Virtual` or `Stored` must be explicit.

## SELECT

Use `select(...)` for result columns and expressions, and `from(...)` for their source rows.
`where` filters rows, `orderBy` sorts the result, and `limit` and `offset` restrict its size.

```kotlin
// SQL: SELECT id, email
//      FROM users
//      WHERE email <> ? AND display_name IS NOT NULL
//      ORDER BY email ASC, id DESC
//      LIMIT 50 OFFSET 0
val users = database.select(Users.id, Users.email)
    .from(Users)
    .where((Users.email neq "") and Users.displayName.isNotNull())
    .orderBy(Users.email.asc(), Users.id.desc())
    .limit(50)
    .offset(0)
    .all()

// SQL: SELECT id, email FROM users WHERE id = ?
val user = database.select(Users.id, Users.email)
    .from(Users)
    .where(Users.id eq userId)
    .oneOrNull()

// SQL: SELECT id, email FROM users
val summaries = database.select(Users.id, Users.email)
    .from(Users)
    .stream()
    .map { row -> UserSummary(row[Users.id], row[Users.email]) }
    .toList()
```

| Execution | Result |
| --- | --- |
| `.all()` | `List<SqlRow>` |
| `.stream()` | `Flow<SqlRow>` |
| `.one()` | Exactly one row; fails for zero or multiple rows |
| `.oneOrNull()` | `null` for zero rows; fails for multiple rows |

Read a row with its selected column or alias, not a string name.
`row[Users.id]` is `Uuid`; `row[expressionAlias]` has the aliased expression's type.

| SQL concept | Kagiroi |
| --- | --- |
| `a = ?`, `a <> ?` | `a eq value`, `a neq value` |
| `a > ?`, `a >= ?` | `a gt value`, `a gte value` |
| `a IS NULL` | `a.isNull()` |
| `a IS [NOT] DISTINCT FROM ?` | `a isNotDistinctFrom value` / `a isDistinctFrom value` |
| `p AND q`, `p OR q` | `p and q`, `p or q` |
| `ORDER BY a ASC/DESC [NULLS FIRST/LAST]` | `a.asc()` / `a.desc()`, then `.nullsFirst()` / `.nullsLast()` |
| `LIKE ?` | `column like pattern` |

### NULLS FIRST and NULLS LAST

Use an explicit NULL placement when the position of nullable values matters.
The syntax applies to result, set-operation, window, and `WITHIN GROUP` ordering.
PostgreSQL/PGlite, SQLite/D1, and Oracle support it; MySQL, MariaDB, and SQL Server reject it.

```kotlin
// SQL (PostgreSQL/PGlite, SQLite/D1, Oracle):
// SELECT id FROM users ORDER BY display_name ASC NULLS LAST, email DESC NULLS FIRST
val orderedUsers = database.select(Users.id)
    .from(Users)
    .orderBy(Users.displayName.asc().nullsLast(), Users.email.desc().nullsFirst())
    .all()
```

### DISTINCT, aggregates, and GROUP BY

`distinct()` removes duplicate result rows.
`countDistinct(x)` is `COUNT(DISTINCT x)`, a separate operation.

```kotlin
// SQL: SELECT DISTINCT organization_id FROM users ORDER BY organization_id ASC
val organizationIds = database.select(Users.organizationId)
    .distinct()
    .from(Users)
    .orderBy(Users.organizationId.asc())
    .all()

// SQL: SELECT organization_id, COUNT(*) AS order_count, SUM(amount) AS total_amount
//      FROM orders WHERE active = ? GROUP BY organization_id
//      HAVING COUNT(*) > ? ORDER BY total_amount DESC
val orderCount = count().alias("order_count")
val totalAmount = sum(Orders.amount).alias("total_amount")
val totals = database.select(Orders.organizationId, orderCount, totalAmount)
    .from(Orders)
    .where(Orders.active eq true)
    .groupBy(Orders.organizationId)
    .having(count() gt 10L)
    .orderBy(totalAmount.desc())
    .all()
```

`GROUP BY` groups rows with the same values; an aggregate returns one value per group.
In an aggregate query, every selected table value must be a group key or an aggregate input.
`count` is `Long`. `sum`, `avg`, `min`, and `max` are normally nullable because an empty
input has no value.

### PostgreSQL-only DISTINCT ON and ILIKE

Import `dev.quwac.kagiroi.postgres.distinctOn` or `ilike` to opt into PostgreSQL/PGlite syntax.
`DISTINCT ON` keeps one row per key, selected by `ORDER BY`; start the ordering with the distinct key.

```kotlin
// SQL (PostgreSQL/PGlite): SELECT DISTINCT ON (organization_id) organization_id, id, email
//                          FROM users ORDER BY organization_id ASC, id DESC
// import dev.quwac.kagiroi.postgres.distinctOn
val newestUsers = database.select(Users.organizationId, Users.id, Users.email)
    .from(Users)
    .distinctOn(Users.organizationId)
    .orderBy(Users.organizationId.asc(), Users.id.desc())
    .all()

// SQL (PostgreSQL/PGlite): SELECT id FROM users WHERE email ILIKE ?
// import dev.quwac.kagiroi.postgres.ilike
val matchingUsers = database.select(Users.id)
    .from(Users)
    .where(Users.email ilike "%@example.com")
    .all()
```

`isNotDistinctFrom` treats two SQL NULL values as equal; `isDistinctFrom` treats one NULL and one
non-NULL value as different.
They use PostgreSQL/PGlite's `IS [NOT] DISTINCT FROM`, SQLite/D1's `IS` / `IS NOT`, and
MySQL/MariaDB's null-safe equality operator.

```kotlin
// SQL (PostgreSQL/PGlite): SELECT id FROM users
//                          WHERE display_name IS NOT DISTINCT FROM ?
val exactDisplayName = database.select(Users.id)
    .from(Users)
    .where(Users.displayName isNotDistinctFrom requestedDisplayName)
    .all()
```

Common functions are `lower`, `upper`, `trim`, `length`, `substring`, `replace`,
`concat`, `coalesce`, `nullIf`, `abs`, `round`, `floor`, `ceil`, `power`, and `sqrt`.
Use `.alias("name")` when a function result must be read from a row.

```kotlin
// SQL: SELECT users.id, LOWER(users.email) AS normalized_email,
//             COALESCE(users.nickname, ?) AS display_name,
//             CASE WHEN orders.amount >= ? THEN ? ELSE ? END AS category
//      FROM users INNER JOIN orders ON orders.user_id = users.id
//      WHERE LOWER(users.email) = ?
val normalizedEmail = lower(Users.email).alias("normalized_email")
val displayName = coalesce(Users.nickname, literal("anonymous")).alias("display_name")
val category = case<String> {
    whenThen(Orders.amount gte highThreshold, "high")
    elseValue("standard")
}.alias("category")

val row = database.select(Users.id, normalizedEmail, displayName, category)
    .from(Users)
    .innerJoin(Orders, on = Orders.userId eq Users.id)
    .where(lower(Users.email) eq requestedEmail)
    .one()
```

`literal(value)` makes a bound parameter.
`cast(expr, stringType())` or `expr.castTo(stringType())` makes a typed CAST explicit.
For JSON, regular expressions, spatial values, and other APIs without a common surface, use a
dialect module or parameterized raw SQL.

### ROLLUP, CUBE, and GROUPING SETS

These GROUP BY elements produce subtotals and grand totals.
Kagiroi does not rewrite them to `UNION ALL`.
A subtotal can make a normally non-null group key SQL NULL, so select it through `.optional`.

```kotlin
// SQL: SELECT country, city, SUM(amount) AS total
//      FROM sales GROUP BY ROLLUP (country, city)
val country = Sales.country.optional
val city = Sales.city.optional
val total = sum(Sales.amount).alias("total")
val rows = database.select(country, city, total)
    .from(Sales)
    .groupBy(rollup(Sales.country, Sales.city))
    .all()

// SQL: SELECT country, product, SUM(amount) AS total
//      FROM sales GROUP BY GROUPING SETS ((country, product), (country), ())
val explicitRows = database.select(country, Sales.product.optional, total)
    .from(Sales)
    .groupBy(
        groupingSets(
            groupingSet(Sales.country, Sales.product),
            groupingSet(Sales.country),
            grandTotal(),
        ),
    )
    .all()
```

`grouping(expr)` distinguishes a data NULL from a subtotal NULL with `0` / `1`.
SQLite/D1 reject advanced grouping.
MySQL accepts part of `rollup`; MariaDB accepts only direct-expression `rollup`.

### JOIN

A JOIN combines two row sets by a condition.
An INNER JOIN keeps matching pairs; a LEFT JOIN retains its left row and makes the missing right
side NULL.

```kotlin
// SQL: SELECT users.id, organizations.name
//      FROM users LEFT JOIN organizations ON users.organization_id = organizations.id
//      ORDER BY organizations.name ASC
val organizationName = Organizations.name.optional
val rows = database.select(Users.id, organizationName)
    .from(Users)
    .leftJoin(Organizations, on = Users.organizationId eq Organizations.id)
    .orderBy(organizationName.asc())
    .all()

val name: String? = rows.first()[organizationName]
```

Select columns from a possibly missing outer-join side through `.optional`.
That is the right side of LEFT JOIN, the left side of RIGHT JOIN, and both sides of FULL OUTER JOIN.
Kagiroi does not decode a SQL NULL as a non-null Kotlin value.

| SQL | Kagiroi |
| --- | --- |
| `INNER JOIN ... ON ...` | `.innerJoin(source, on = predicate)` |
| `LEFT/RIGHT/FULL OUTER JOIN` | `.leftJoin` / `.rightJoin` / `.fullOuterJoin` |
| `CROSS JOIN` | `.crossJoin(source)` |
| `JOIN ... USING (id)` | `...JoinUsing(source) { using(left, right) }` |

```kotlin
// SQL: SELECT u.id, o.name
//      FROM users AS u INNER JOIN organizations AS o USING (organization_id)
val user = Users.alias("u")
val organization = Organizations.alias("o")
val query = select(user[Users.id], organization[Organizations.name])
    .from(user)
    .innerJoinUsing(organization) {
        using(user[Users.organizationId], organization[Organizations.organizationId])
    }
```

`USING` columns need the same output name and compatible Kotlin and storage types.
SQL Server does not support `USING`, and Kagiroi does not rewrite it to `ON`.
MySQL and MariaDB do not support FULL OUTER JOIN.

Use `alias(name)` when a table appears more than once, and read a column as `alias[Users.id]`.
For a derived relation that uses rows already introduced to its left, use `lateral(name) { ... }`
with `.crossJoinLateral(...)` or `.leftJoinLateral(...)`.

```kotlin
// SQL: SELECT users.id, latest_order.id
//      FROM users CROSS JOIN LATERAL (
//        SELECT id FROM orders WHERE orders.user_id = users.id ORDER BY created_at DESC LIMIT 1
//      ) AS latest_order
val latestOrder = lateral("latest_order") {
    select(Orders.id)
        .from(Orders)
        .where(Orders.userId eq Users.id)
        .orderBy(Orders.createdAt.desc())
        .limit(1)
}
val rows = database.select(Users.id, latestOrder[Orders.id])
    .from(Users)
    .crossJoinLateral(latestOrder)
    .all()
```

SQLite/D1 and MariaDB do not support LATERAL.
SQL Server and Oracle render `CROSS APPLY` and `OUTER APPLY`, respectively.

### Window functions

A window function computes a rank or running value without collapsing its input rows.
The `orderBy` inside `OVER (...)` is not the final result order.

```kotlin
// SQL: SELECT id,
//        ROW_NUMBER() OVER (PARTITION BY organization_id ORDER BY created_at ASC) AS row_number,
//        SUM(amount) OVER (
//          PARTITION BY organization_id ORDER BY created_at ASC
//          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
//        ) AS running_total,
//        LAG(amount) OVER (PARTITION BY organization_id ORDER BY created_at ASC) AS previous_amount
//      FROM orders
val rowNumber = rowNumber()
    .over {
        partitionBy(Orders.organizationId)
        orderBy(Orders.createdAt.asc())
    }
    .alias("row_number")
val runningTotal = sum(Orders.amount)
    .over {
        partitionBy(Orders.organizationId)
        orderBy(Orders.createdAt.asc())
        rows(between(unboundedPreceding, currentRow))
    }
    .alias("running_total")
val previousAmount = lag(Orders.amount)
    .over {
        partitionBy(Orders.organizationId)
        orderBy(Orders.createdAt.asc())
    }
    .alias("previous_amount")

val analytics = database.select(Orders.id, rowNumber, runningTotal, previousAmount)
    .from(Orders)
    .all()
```

| Purpose | API | Type |
| --- | --- | --- |
| Sequence and rank | `rowNumber()`, `rank()`, `denseRank()`, `ntile(n)` | `Long` |
| Relative rank | `percentRank()`, `cumeDist()` | `Double` |
| Previous or next value | `lag(x)`, `lead(x, offset, default)` | `T?` |
| First, last, or Nth value | `firstValue(x)`, `lastValue(x)`, `nthValue(x, n)` | Input type; Nth is `T?` |
| Aggregate in a window | `.over { ... }` on `count`, `sum`, `avg`, `min`, or `max` | Aggregate type |

`lag` and `lead` require `orderBy`.
Use `.nullsFirst()` or `.nullsLast()` on an order inside `over { ... }` when its input is nullable.
The default frame for `lastValue` and `nthValue` can end at the current row, so specify a
full-partition frame when that is needed.

```kotlin
// SQL: SELECT LAST_VALUE(amount) OVER (
//        ORDER BY created_at ASC
//        RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
//      ) AS partition_last_amount
val partitionLastAmount = lastValue(Orders.amount)
    .over {
        orderBy(Orders.createdAt.asc())
        range(between(unboundedPreceding, unboundedFollowing))
    }
    .alias("partition_last_amount")

// SQL: SELECT SUM(amount) OVER (
//        ORDER BY amount ASC GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW EXCLUDE TIES
//      ) AS peer_total
val peerTotal = sum(Orders.amount)
    .over {
        orderBy(Orders.amount.asc())
        groups(between(preceding(1), currentRow))
        excludeTies()
    }
    .alias("peer_total")
```

`ROWS` counts physical rows, `RANGE` counts peer rows with equal sort values, and `GROUPS`
counts peer groups.
Portable `range` supports only no-offset boundaries.
`groups`, frame exclusions, named windows, and `nthValue` vary by dialect.
Unsupported forms fail before execution; they are not translated to another SQL shape.

You cannot use a window result directly in `where`, `having`, or a JOIN condition.
Move it into `asTable` or a CTE, then filter from the outer query.

```kotlin
// SQL: SELECT id FROM (
//        SELECT id, ROW_NUMBER() OVER (
//          PARTITION BY organization_id ORDER BY created_at ASC
//        ) AS row_number FROM orders
//      ) AS ranked WHERE row_number > ?
val ranked = database.select(Orders.id, rowNumber).from(Orders).asTable("ranked")
val rankedRows = database.select(ranked[Orders.id])
    .from(ranked)
    .where(ranked[rowNumber] gt 1L)
    .all()
```

`RESPECT NULLS` and `IGNORE NULLS` are dialect-module extensions.
MySQL exposes `respectNulls()`; SQL Server 2022+ and Oracle expose both.
The common API leaves NULL treatment unspecified elsewhere.

### WITHIN GROUP

`percentileCont`, `percentileDisc`, `mode`, and `hypotheticalRank` are aggregates separate
from window `OVER`.
They come from the PostgreSQL/PGlite and Oracle modules.

```kotlin
// SQL: SELECT PERCENTILE_CONT(?) WITHIN GROUP (ORDER BY amount ASC) AS median
val median = percentileCont(0.5)
    .withinGroup(Orders.amount.asc())
    .alias("median")
```

`percentileCont` is nullable `Double`; `percentileDisc` and `mode` have the ordered
expression's nullable type.
MySQL, MariaDB, SQLite/D1, and SQL Server have no common WITHIN GROUP API.

## Combine queries, subqueries, and CTEs

### UNION, INTERSECT, and EXCEPT

Two queries must select the same number of values with the same Kotlin types, storage mappings, and
nullability in the same order.
After a set operation, read rows and order results with the left projection.

```kotlin
val userId = Users.id.alias("user_id")
val currentUsers = select(userId, Users.name).from(Users)
val archivedUsers = select(ArchivedUsers.id, ArchivedUsers.name).from(ArchivedUsers)

// SQL: (SELECT id AS user_id, name FROM users)
//      UNION ALL (SELECT id, name FROM archived_users)
//      ORDER BY user_id ASC LIMIT 100
val allUsers = currentUsers.unionAll(archivedUsers)
    .orderBy(userId.asc())
    .limit(100)

// SQL: SELECT id AS user_id, name FROM users
//      INTERSECT SELECT id, name FROM archived_users
val commonUsers = currentUsers.intersect(archivedUsers)

// SQL: SELECT id AS user_id, name FROM users
//      EXCEPT SELECT id, name FROM archived_users
val onlyCurrentUsers = currentUsers.except(archivedUsers)
```

`union`, `intersect`, and `except` remove duplicates; `unionAll` retains them.
`intersectAll` and `exceptAll` are duplicate-preserving operations for supported dialects.
Kagiroi does not emulate an unavailable set operation.

### scalar, EXISTS, and derived tables

A single-column query can become a scalar subquery through `scalar()`.
Zero rows become SQL NULL; multiple rows are a database error.

```kotlin
// SQL: SELECT users.id,
//        (SELECT amount FROM orders WHERE orders.user_id = users.id
//         ORDER BY created_at DESC LIMIT 1) AS latest_amount
//      FROM users
//      WHERE users.organization_id IN (SELECT id FROM organizations WHERE active = ?)
//        AND EXISTS (SELECT 1 FROM orders WHERE orders.user_id = users.id)
val latestAmount = select(Orders.amount)
    .from(Orders)
    .where(Orders.userId eq Users.id)
    .orderBy(Orders.createdAt.desc())
    .limit(1)
    .scalar()
    .alias("latest_amount")
val activeOrganizationIds = select(Organizations.id)
    .from(Organizations)
    .where(Organizations.active eq true)
val rows = database.select(Users.id, latestAmount)
    .from(Users)
    .where(
        (Users.organizationId.inSubquery(activeOrganizationIds)) and
            exists(select(Orders.id).from(Orders).where(Orders.userId eq Users.id)),
    )
    .all()
```

`asTable("name")` makes a query result the FROM source of the next query.
Refer to a selected column or alias as `derived[projection]`.
There is no string-based column lookup.

```kotlin
// SQL: SELECT active_users.id, active_users.normalized_email
//      FROM (SELECT id, LOWER(email) AS normalized_email FROM users WHERE active = ?) AS active_users
//      WHERE active_users.normalized_email = ?
val normalizedEmail = lower(Users.email).alias("normalized_email")
val activeUsers = select(Users.id, normalizedEmail)
    .from(Users)
    .where(Users.active eq true)
    .asTable("active_users")
val row = database.select(activeUsers[Users.id], activeUsers[normalizedEmail])
    .from(activeUsers)
    .where(activeUsers[normalizedEmail] eq "alice@example.com")
    .one()
```

### CTE

A CTE is a named temporary query result.
Create it with `asCte` and use it only inside its `with(...)` block.
Pass dependencies first.

```kotlin
// SQL: WITH active_users AS (
//        SELECT id, organization_id FROM users WHERE active = ?
//      )
//      SELECT id FROM active_users WHERE id > ? ORDER BY id ASC LIMIT 20
val activeUsers = select(Users.id, Users.organizationId)
    .from(Users)
    .where(Users.active eq true)
    .asCte("active_users")
val activeUserId = activeUsers[Users.id]
val rows = with(activeUsers) {
    database.select(activeUserId)
        .from(activeUsers)
        .where(activeUserId gt minimumUserId)
        .orderBy(activeUserId.asc())
        .limit(20)
}.all()
```

The CTE keeps its source query's types and projection handles.
A non-recursive CTE body is SELECT-only. Writable CTEs, forward references, and materialization
hints are unavailable.
`with(...)` can also scope a typed UPDATE, DELETE, or INSERT ... SELECT.

### Recursive CTE

`recursiveCte` joins an anchor and recursive member with `UNION ALL`.
The member places the callback's `self` directly once as a FROM or JOIN source.

```kotlin
// SQL: WITH RECURSIVE numbers(n) AS (
//        SELECT 1 AS n
//        UNION ALL
//        SELECT n + 1 FROM numbers WHERE n < 10
//      )
//      SELECT n FROM numbers ORDER BY n ASC
val n = literal(1).alias("n")
val numbers = recursiveCte(name = "numbers", anchor = select(n)) { self ->
    select(self[n] + 1)
        .from(self)
        .where(self[n] lt 10)
}
val number = numbers[n]
val rows = with(numbers) {
    database.select(number).from(numbers).orderBy(number.asc())
}.all()
```

The anchor determines result-column types, nullability, and names.
The member must return exactly the same types and storage mappings in every position.
A recursive member cannot use DISTINCT, GROUP BY, HAVING, aggregates, windows, ORDER BY, LIMIT,
or OFFSET.
SQLite/D1, PostgreSQL/PGlite, MySQL, and MariaDB render `WITH RECURSIVE`; SQL Server and Oracle
render `WITH`.

## INSERT, UPDATE, and DELETE

`set` accepts the writable column's Kotlin type.
Each INSERT row sets the same columns and sets at least one.
`deleteFrom` requires `where` to prevent an accidental full deletion.
Use `deleteAllFrom` explicitly to delete every row.

```kotlin
// SQL: INSERT INTO users (id, email, display_name)
//      VALUES (?, ?, NULL), (?, ?, ?)
database.insertInto(Users)
    .values {
        set(Users.id, userId)
        set(Users.email, "alice@example.com")
        set(Users.displayName, null)
    }
    .values {
        set(Users.id, anotherUserId)
        set(Users.email, "bob@example.com")
        set(Users.displayName, "Bob")
    }
    .execute()

// SQL: UPDATE users SET display_name = ? WHERE id = ?
database.update(Users) { set(Users.displayName, "Alice") }
    .where(Users.id eq userId)
    .execute()

// SQL (PostgreSQL/PGlite, SQLite/D1): UPDATE users SET display_name = profiles.display_name
//                                     FROM profiles WHERE users.id = profiles.user_id
database.update(Users) { set(Users.displayName, Profiles.displayName) }
    .from(Profiles)
    .where(Users.id eq Profiles.userId)
    .execute()

// SQL: DELETE FROM users WHERE id = ?
database.deleteFrom(Users)
    .where(Users.id eq userId)
    .execute()

// SQL: DELETE FROM users
database.deleteAllFrom(Users).execute()
```

For a dynamic multi-row INSERT, use `NonEmptyList` to make an empty INSERT impossible by type.

```kotlin
val users = nonEmptyListOf(
    User(userId, "alice@example.com", null),
    User(anotherUserId, "bob@example.com", "Bob"),
)

// SQL: INSERT INTO users (id, email, display_name) VALUES (?, ?, ?), (?, ?, ?)
database.insertInto(Users)
    .values(users) { user ->
        set(Users.id, user.id)
        set(Users.email, user.email)
        set(Users.displayName, user.displayName)
    }
    .execute()
```

For an arbitrary `Iterable`, decide how to handle empty input first, for example with
`NonEmptyList.from(values) ?: return`.

### INSERT ... SELECT and write results

Target columns and source projections must match by position in type, storage mapping, and
nullability.
One INSERT cannot mix VALUES and a SELECT source.

```kotlin
// SQL: WITH archived_users AS (
//        SELECT id, email FROM users WHERE deleted = ?
//      )
//      INSERT INTO user_archive (id, email) SELECT id, email FROM archived_users
val archivedUsers = select(Users.id, Users.email)
    .from(Users)
    .where(Users.deleted eq true)
    .asCte("archived_users")
val archivedId = archivedUsers[Users.id]
val archivedEmail = archivedUsers[Users.email]
with(archivedUsers) {
    database.insertInto(UserArchive, UserArchive.id, UserArchive.email)
        .from(select(archivedId, archivedEmail).from(archivedUsers))
}.execute()

// SQL: INSERT INTO users (email) VALUES (?) RETURNING id, email
val returnedRow = database.insertInto(Users)
    .values { set(Users.email, "alice@example.com") }
    .returning(Users.id, Users.email)
    .one()
```

SQLite, D1, PostgreSQL, and PGlite use `returning(...)`.
SQL Server has `output(...)`; Oracle has `returningInto(...)`.
MySQL and MariaDB return the driver's `affectedRows` from `.execute()`.

### Dialect-specific INSERT conflict handling

There is no common `upsert`.
Databases differ in conflict-target selection and in which row an update may reference.

```kotlin
// SQL (PostgreSQL): INSERT INTO users (id, email, name) VALUES (?, ?, ?)
//                   ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name
// import dev.quwac.kagiroi.postgres.onConflict
database.insertInto(Users)
    .values {
        set(Users.id, userId)
        set(Users.email, email)
        set(Users.name, name)
    }
    .onConflict(Users.email) {
        doUpdate { set(Users.name, excluded(Users.name)) }
    }
    .execute()

// SQL (SQLite/D1): INSERT INTO users (email, name) VALUES (?, ?)
//                  ON CONFLICT (email) DO UPDATE SET name = excluded.name
// import dev.quwac.kagiroi.sqlite.onConflict
database.insertInto(Users)
    .values { set(Users.email, email); set(Users.name, name) }
    .onConflict(Users.email) { doUpdate { set(Users.name, excluded(Users.name)) } }
    .execute()

// SQL (MySQL): INSERT INTO counters (id, count) VALUES (?, ?) AS kagiroi_inserted
//              ON DUPLICATE KEY UPDATE count = counters.count + kagiroi_inserted.count
// SQL (MariaDB): INSERT INTO counters (id, count) VALUES (?, ?)
//                ON DUPLICATE KEY UPDATE count = counters.count + VALUES(count)
// import dev.quwac.kagiroi.mysql.onDuplicateKeyUpdate
database.insertInto(Counters)
    .values { set(Counters.id, counterId); set(Counters.count, increment) }
    .onDuplicateKeyUpdate {
        set(Counters.count, Counters.count + inserted(Counters.count))
    }
    .execute()
```

PostgreSQL also offers `onConflictConstraint(name)` for a named constraint.
SQLite/D1 permits one conflict clause per INSERT.
MySQL/MariaDB take no conflict target and follow their server's duplicate-key rules.
Use raw SQL for SQL Server/Oracle MERGE, multiple SQLite conflict clauses, and REPLACE.

### D1 batch

`D1Database.batch` requires at least one statement.

```kotlin
// SQL: UPDATE users SET active = ? WHERE id = ?;
//      DELETE FROM user_sessions WHERE user_id = ?;
// import dev.quwac.kagiroi.d1.*
val statements = nonEmptyListOf(
```

## Application schema projection

`schema(...)` declares the explicit table roots managed by schema-aware external tools. It is a
Kagiroi API; it does not define a second table DSL or persist a schema snapshot.

```kotlin
// import dev.quwac.kagiroi.schema.schema
object Users : Table("users") {
    val id = long("id").identity().primaryKey()
    val displayName = string("display_name").renamedFrom("name")
    val email = string("email")
}

val appSchema = schema(Users)
val projectionJson = appSchema.project().encode()
```

The versioned Schema Projection contains the current physical objects and separately records
`renamedFrom(...)` lineage. It is a deterministic integration boundary: external tools consume it
without reading Kagiroi's runtime Table, Column, or expression implementation classes. The
projection itself neither connects to a database nor generates SQL.

## Creating tables, indexes, and ALTER TABLE

`database.execute { ... }` executes DDL immediately in source order.
It does not start a transaction.

```kotlin
// SQL: CREATE TABLE IF NOT EXISTS users (
//        id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
//        display_name VARCHAR NOT NULL,
//        email VARCHAR NOT NULL,
//        active BOOLEAN NOT NULL
//      );
//      CREATE INDEX users_display_name_idx ON users (display_name);
//      CREATE UNIQUE INDEX users_display_name_email_idx ON users (display_name, email);
//      CREATE INDEX users_active_email_idx ON users (LOWER(email) ASC)
//        INCLUDE (id) WHERE active = ?;
//      DROP INDEX users_display_name_idx;
//      DROP TABLE IF EXISTS users;
database.execute {
    createTable(Users, ifNotExists = true)
    createIndexes(Users)
    dropIndex("users_display_name_idx", Users)
    dropTable(Users, ifExists = true)
}
```

`createIndexes(Users)` uses the index metadata declared on `Users`, in declaration order.
An unavailable option throws `UnsupportedDdlOperation` during rendering.

```kotlin
object UsersMigration : Table("users") {
    val nickname = string("nickname").nullable()
}

// SQL: ALTER TABLE users ADD COLUMN nickname VARCHAR;
//      ALTER TABLE users ALTER COLUMN email SET NOT NULL;
//      ALTER TABLE users ADD CONSTRAINT uq_users_org_email UNIQUE (organization_id, email);
database.execute(
    alterTable(Users) {
        addColumn(UsersMigration.nickname)
        setNotNull(Users.email)
        addUnique(Users.organizationId, Users.email, name = "uq_users_org_email")
    },
)

// SQL: ALTER TABLE users RENAME COLUMN email TO login_email
database.execute(alterTable(Users) { renameColumn(Users.email, "login_email") })
```

`alterTable` preserves the specified order.
Put `renameColumn` and `renameTable` last in their block.
SQLite/D1 do not rebuild a table, so only direct SQLite ALTER operations are available.
Use raw SQL for SQL Server default-constraint lookup and MySQL/MariaDB changes that would require
reconstructing a complete column definition.

## Transactions, savepoints, raw SQL, and errors

```kotlin
// SQL: BEGIN;
//      UPDATE users SET display_name = ? WHERE id = ?;
//      SAVEPOINT ...; DELETE FROM sessions WHERE user_id = ?; RELEASE SAVEPOINT ...;
//      COMMIT;
database.transaction {
    update(Users) { set(Users.displayName, "Alice") }
        .where(Users.id eq userId)
        .execute()
    savepoint {
        deleteFrom(Sessions)
            .where(Sessions.userId eq userId)
            .execute()
    }
}

// SQL: UPDATE users SET display_name = ? WHERE id = ?
database.executeRaw("UPDATE users SET display_name = ? WHERE id = ?", listOf("Alice", userId))

// SQL: SELECT id FROM users WHERE id = ?
val rawRows = database.queryRaw("SELECT id FROM users WHERE id = ?", listOf(userId))
```

`transaction` commits on normal completion and rolls back on an exception.
Nested transactions are unavailable. Use `savepoint` inside a transaction for partial rollback.
D1 does not support interactive transactions or savepoints.

For SQL outside the common API, use `executeRaw(sql, parameters)` or
`queryRaw(sql, parameters)`.
Pass values in `parameters`; do not interpolate them into the SQL string.

When a driver can identify a rule failure, it reports `ConstraintViolation` with a
`ConstraintKind` such as `UNIQUE`, `FOREIGN_KEY`, `NOT_NULL`, or `CHECK`.
Kotlin types do not establish the validity of existing database rows or external input.

## Dialect guide

| Feature | Common API behavior |
| --- | --- |
| FULL OUTER JOIN | SQLite/D1, PostgreSQL/PGlite, SQL Server, Oracle; MySQL/MariaDB reject before execution |
| JOIN ... USING | Supported dialects except SQL Server; use explicit `ON` on SQL Server |
| LATERAL | PostgreSQL/PGlite, MySQL, SQL Server, Oracle; SQLite/D1 and MariaDB reject it |
| Advanced GROUP BY | Complete on PostgreSQL/PGlite, SQL Server, Oracle; limited on MySQL/MariaDB; rejected on SQLite/D1 |
| Window GROUPS / exclusion | PostgreSQL/PGlite, SQLite/D1, Oracle; other dialects reject some forms before execution |
| `NULLS FIRST` / `NULLS LAST` query ordering | PostgreSQL/PGlite, SQLite/D1, Oracle; MySQL/MariaDB and SQL Server reject it |
| `DISTINCT ON`, `ILIKE` | PostgreSQL/PGlite module extensions |
| `IS [NOT] DISTINCT FROM` | PostgreSQL/PGlite; SQLite/D1 renders `IS` / `IS NOT`; MySQL/MariaDB render null-safe equality |
| `UPDATE ... FROM` | PostgreSQL/PGlite and SQLite/D1; other dialects reject it |
| `returning` | SQLite/D1, PostgreSQL/PGlite; SQL Server has `output`; Oracle has `returningInto` |
| Sequence | PostgreSQL/PGlite, MariaDB, SQL Server, Oracle |

The common API does not emulate behavior that differs across dialects.
Choose the dialect-specific API, or raw SQL when the dialect does not support the feature.

## Raw SQL boundary

Kagiroi does not accept SQL fragments as expressions.
Use `executeRaw(sql, parameters)` or `queryRaw(sql, parameters)` for a complete,
parameterized statement outside this API.

- **SELECT and expressions:** simple `CASE`, implicit `ELSE NULL`, `QUALIFY`, `FROM LAST`, and
  vendor-specific statistical or percentile syntax.
- **JOIN and relation syntax:** `NATURAL JOIN`, automatic join-condition discovery, table functions,
  RIGHT/FULL LATERAL, automatic LATERAL/APPLY detection, and DML APPLY.
- **CTEs:** writable CTE bodies, forward references, materialization hints, recursive `UNION` distinct,
  mutual recursion, `SEARCH`, `CYCLE`, automatic cycle detection, and SQL Server `MAXRECURSION`.
- **DML:** `DELETE ... USING`, target correlation, a generic `upsert`, `MERGE`, `REPLACE`,
  `INSERT IGNORE`, catalog lookup, retry, and application-side emulation.
- **Generic DDL:** index methods and operator classes, index-level `NULLS FIRST` / `NULLS LAST`, prefix indexes,
  full-text, spatial, bitmap, columnstore, and other broad vendor options.

- `intersectAll()` and `exceptAll()` are rejected by SQL Server and SQLite/D1.
- MariaDB rejects the default argument of `lag` and `lead`.
- MariaDB rejects CTE-scoped DML. Oracle accepts it only for INSERT ... SELECT, not UPDATE or DELETE.
- MySQL and MariaDB expose `ON DUPLICATE KEY UPDATE`; they do not share PostgreSQL/SQLite `ON CONFLICT`.
